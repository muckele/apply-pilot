# Owner-local synthetic document review receipts

Before manifest consent or credential input, the document-review launcher displays that it will persist only a sanitized final receipt in the private owner-local location, with the directory/file permission modes. It saves each returned sanitized final receipt before printing its final JSON. It creates a unique `.apply-pilot-document-review-receipt-*` directory directly in the current owner's home directory with mode `0700`, then publishes `receipt.json` with mode `0600`. The final stdout object keeps the original `status` and `receipt` and adds `receiptPersistence`: either `saved` with an absolute `path` and SHA-256 of the exact saved bytes, or `failed` with the bounded `SAFE_RECEIPT_WRITE_FAILED` code. A persistence failure exits nonzero while still printing the original safe result when stdout is available. It does not repeat generation or change the original review outcome.

The saved file contains only `{ status, receipt }`, including existing hashes, exact head, token/cost counters, bounded failure paths/categories and actual recorded review dispositions/attestations. A strict allowlist rejects unknown fields at every level, unrecognized string values and credential matches before writing. Credentials, capability URLs, provider output, generated documents, source/applicant text and raw errors are excluded. The file is written exclusively to a temporary file, synced, and atomically linked to the final name without overwriting existing files or symlinks; the staging name is removed and the directory is synced. Each run has its own directory, including concurrent runs. The parent must be a real owner-controlled directory without group/world write permissions. No database, remote storage or Library upload is involved.

`SIGINT`, `SIGTERM` and Terminal `SIGHUP` request the same existing cancellation path. When the runner returns its stopped receipt, it is saved just like successful/revision outcomes or generation failures. Original review expiry and explicit cancellation remain bounded stopped outcomes, not invented owner decisions. Closing a browser tab alone still does not cancel the review or extend its original deadline. A hard kill, power loss, failed storage or an exception before a final receipt exists cannot guarantee a receipt; the launcher does not infer usage or decisions in those cases. A write may already have atomically published before a later filesystem sync or stdout failure; no replacement or retry is attempted.

The historical `c4616f4` exercise printed its receipt only to stdout; after Terminal closed, no persisted receipt was found through the approved bounded route. Its actual final usage, cost and recorded owner decisions remain unverified. This change cannot reconstruct them and authorizes no provider call or paid retry. Existing model, spending bounds, no-retry/no-fallback behavior, source-fidelity checks and actual export verification remain unchanged.

Offline tests cover approved/revision receipts, generation failure, incomplete/cancelled/expired/signal outcomes, Terminal hangup cleanup, save-before-stdout ordering, write errors and staging cleanup, strict allowlist/secret rejection, concurrent unique files, permission bits, exact byte hashes and refusal to overwrite existing regular files or symlinks. These are synthetic tests, not a new paid result.
