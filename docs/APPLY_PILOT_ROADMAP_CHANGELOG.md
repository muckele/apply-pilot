## Version 2.0 — 2026-09-20 — Web-first delivery amendment

### Why this revision exists
Mathew identified required-extension onboarding as a problem for Safari/Firefox users and less-technical applicants. The roadmap now treats the web app as the product and managed-browser execution as the preferred public-delivery model, subject to feasibility and safety evidence.

### Changes from version 1.0
- P2 **Chrome Copilot** becomes **Managed Application Workspace / Browser Copilot**.
- Extensions move from the main dependency chain to optional convenience surfaces.
- The current separate Chromium runtime remains the local technical/self-beta baseline.
- Technical Human-Submit acceptance and no-download public-release acceptance are separate milestones.
- An early hosted feasibility track is added without authorizing cloud spending or replacing ongoing multi-ATS work.
- Added architecture for session ownership, automation-versus-human control, viewer access, worker liveness, hosted privacy, manual file handling, and uncertain outcomes.
- Added provider validation and stop/go evidence rather than declaring a browser vendor selected.
- Added runtime/browser dimensions to ATS support records.
- Added separate release gates, risk register, beta/economics model, and detailed agent workflow.
- Updated the reusable master prompt and documentation-adoption prompt, plus a compact future-session starter.
- Added current source research for hosted browser delivery and refreshed selected repository observations. Older external research remains explicitly inherited where not rechecked.
- Removed named-model price scenarios from the active commercial baseline; historical v1 pricing must be revalidated before use. Generic sensitivity formulas remain illustrative.
- Clarified that browser-local data in hosted execution is remote processor-held data, not data confined to the user's laptop.

### Unchanged
Multi-ATS priorities; truth above score; source-linked versus verified distinction; preserved existing values; current writable families; manual contact/source restrictions; one permanent Fill attempt; no agent employer Submit; separate personal-submission attestation; database rules; explicit scope; independently reviewed runtime changes; commit/push/merge/deploy distinctions.
